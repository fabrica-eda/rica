# 実機測定によるSTA表全体の置換

2026-09-23: 全表置換を既定プロファイルへ採用済み。CPU 124.8 MHz／メモリ62.4 MHzを
維持し、温度余裕20%・setup/hold各194 psを含めて残余は **+2/+1 ps**。
JTCKの独立検査各515件、checked bitgen、同一ビットストリームの267実機試験が合格した。
[採用プロファイル](../qualified-measured-sta.json)と
[認定記録](../../toolchain/measurements/2026-09-22-ecp5-sta-replacement/validation.json)に
ツール・表・RTL・ELF・ビットストリームのハッシュを保存する。

既存の遅延表から利用するのはピン名とPIPクラス名だけで、数値は学習にも
補完にも使わない。`build_sta_refined_library.py` が全1,552項目を生成し、Texoの
`--measured-timing-library` が選択速度グレードを一括置換する。部分的な
置換、未測定項目の旧表へのフォールバック、測定ファイルの改変は拒否する。

## 測定とモデル

接続済みLFE5UM5G-85F-EVN、CABGA381、名目12 MHz基板クロックを使用。
リング発振器、PLL位相を約200.32 ps刻みで掃引する捕捉回路、DCCA帰還ループを
実際に配置配線して測定した。外部計測器やシミュレーションの遅延ラベルは使わない。

- 474経路サンプル、学習261件・独立配置／刺激による検証213件（追加測定38件を含む）。
- LUT、carry、PFUMX/L6MUX、FFデータ・CE・LSR、DP16KDの両ポートの
  アドレス・データ・CE・WE・CS・OCE・リセット解放、NOREG/OUTREG出力、
  MULT18X18Dの全入力ビット・符号制御、DCCA帰還を測定。
- 373配線クラス、1,097セルアーク、82setup/hold項目を置換する。
- DSPの入力ビットiは積のi未満のビットへ影響しない。符号補正は2^18の倍数。
  従来の密な表に含まれた342個の存在しないアークは除去し、実在する
  1,026個を必須にする。未知の経路をゼロ遅延に置き換える操作ではない。
- 一度正解になった後にグリッチが再発する経路を観測したため、最大遅延は
  最後の誤りの後に安定する境界、最小遅延は初期の旧値連続区間の終了を使う。
  採用した各境界は往復掃引で繰り返し観測する。

これは実測経路を説明する**セル・配線の結合モデル**であり、各ピンの物理遅延を
単独で同定したという意味ではない。固定アクセス部分はセルアークへ含め、
FFデータsetupを200 ps、holdを0 psの基準として有効clock-to-Qを同時に求める。
クラスを共有する構造基底で推定した項目と直接の測定根拠をモデル中に残す。
DCCAには実測ループから求めた共通クロック到着時間を使い、相対クロック誤差は
経路検証付きの不確かさに含める。共通遅延の独立したmin/maxばらつきを二重計上しない。

データ経路min/maxには20%の温度余裕を付加し、setup/hold両方の不確かさを
194 psに設定する。学習側189件の交差検証と学習残差だけから決定し、213件の
検証側でも上下限を確認する。carryの下限にだけ26 psの追加補正を持たせ、
他のセルへ一律に転嫁しない。表を整数psへ丸めた後にも474件を再検査する。電源は基板固定電圧で、
独立した電圧掃引と外部校正は行っていない。JTAGGの外部境界など従来の明示的な
未同定境界を、新たに測定済みとは扱わない。

## マージンの内訳

`audit_sta_margin.py` はモデルを変更せず、上下限から外れる残差を分けて監査する。
初期候補（201 ps）では、学習側の下限不足は最大156.945 ps、上限不足は21.091 ps。
検証側では下限167.231 ps、上限193.460 psで、最大の上限不足はDSP経路だった。
201 psは位相刻みを切り上げた最低値でもあるが、初期候補のモデル残差も実際に覆っている。
位相量子化幅は観測区間に含まれるため、201 psを測定器の独立した誤差と呼ばない。

学習側だけを見て157 psへ下げると検証側の境界を覆えないため採用しない。
一律のマージンを減らすには、セル種別と最大／最小側を区別した残差モデル、
相対クロック誤差の分離、および別データでの再検証が必要。
監査の `families` には種類別の残差も保存する。初期候補のデータではBRAM出力・PFUMXの
上限不足は0 psだが、DSPの上限不足193.460 psが同じ一律値に含まれる。
これは削減余地の診断であり、未測定経路も同じ精度になるという認定ではない。
温度分20%と残差マージンは別々に記録する。CPUのタイミング違反量から
逆算してマージンを選ぶことはしない。

## 残差マージン削減の追加測定

201 psを不可避の値とは扱わない。リング平均をmin/maxの等値目標ではなく
片側の包絡条件に直した候補は、学習残差146 psに対し既存検証側が約194 ps必要となり
不合格だった。DSP入力ポート別の係数を加えた候補も128 psに対し約203 ps必要で、
いずれも既定表に採用していない。

DSP比較回路は全36 bitを観測するため、定常状態で変化するbitだけでなく、
同じ入力から到達できる出力上の一時的な不一致も解析の包絡範囲に含める。
`extract_sta_paths_observer.py` は存在しない下位bit依存を除き、その観測範囲を抽出する。
これは各出力アークが単独で遅延同定できたという意味ではない。

追加回路 `dsp-carry-A-02` / `dsp-carry-B-02` は各入力1本だけを切り替え、
積の最上位bitを跨ぐ別のオペランドを使う。測定前に38件を学習用、38件を新しい
検証用として分けた。既存の検証データも学習には戻さない。
`model-refinement-plan.json` に測定前の区分とモデル仮説を保存し、
新しい検証データでモデルを評価する前に追加した、学習データだけの交差検証による
マージン決定手順も日時付きで記録する。温度余裕20%とCPU周波数は変更しない。
追加測定は両側とも往復90捕捉を完了し、全76件の境界を取得した。
学習側189件を1件ずつ除外する交差検証で、FFデータ・配線・クロックに共通の
残差と、DSP・EBR出力・制御チェック等の種類別残差を分ける。種類固有の超過分は
該当セル／チェックの上下限へ反映する。この手順も新しい検証データでの最初の
モデル評価前に固定し、既存175件と追加38件の検証に通ることを採用条件とする。

`corners-refined-01.json` は全474件（学習261件・検証213件）を通過した。
共通マージンは201 psから194 psへ削減し、carryの下限側にだけ26 psを追加する。
他の種類に追加残差補正は不要だった。整数化した全1,552項目も474件を再検証し、
`measured-sta-library-v2.json` に2,441ファイルの根拠ハッシュを保存した。
CPU全体のSTAと267件の実機試験も `native-sta-24` で合格した。
`native-sta-20` はsetup +2 ps／hold -20 psだったが、個別hold配線修正、
競合相手の保護、合法な近傍移動によってhold +1 psまで収束した。
FTDI通信切断時の失敗記録は別ディレクトリに保存し、復旧後の認定は最初から実行した。

## 配線によるLUT入力の入れ替え

LUTの入力ごとの実測遅延が異なるため、STAは論理入力名ではなく、配線済みPIPが
選択した物理入力のアークを使う。配線変更のたびに全体STAとECO用STAの両方で
再解決する。従来の等遅延表では見えなかった入力入れ替え時の誤評価も修正した。
配線探索の順位付けには最速入力との差分を加えるが、報告する配線遅延は変更せず、
STAでは選択されたセルアークを一度だけ加算する。

## 配置探索の修正

近距離の候補は全対象セルを先に試し、その後で移動範囲を広げる。
2・4・8タイルの候補は実測PIPコストで評価し、距離が同じでも配線が速くなる候補を残す。
局所経路評価は有限の空間範囲内でDijkstra法を使う。従来の16段での打切りを除き、
長い有効経路やゼロコスト閉路も正しく処理する。候補の採否は再配線後の全体STAで決める。
一時的な不足が元の不足の2倍以内の候補は、新配置のSTAに基づく配線改善も試す。
中間状態は採用せず、元の全体STAより改善した最終状態だけを一括採用する。
広域移動では空きサイトへの移動と使用済みサイトとの交換を両方候補に残す。
近い交換候補だけで上限に達し、空きBRAMを試せなくなる問題を防ぐ。
単独の移動が行き詰まった場合は、近い未採用候補を最大3件保持し、各候補から
もう1回の移動を試す。最初の移動を直ちに取り消す候補は除外する。全体の時間上限を
共有し、元の配置の全STAを改善した場合だけ2回の移動をまとめて採用する。

## 実装と再検証

測定・解析記録は `toolchain/measurements/2026-09-22-ecp5-sta-replacement/`。
`measured-sta-library-v2.json` に2,441個の入力ハッシュ、全項目の測定根拠、
整数化後の経路検査を保存する。`identities-04/` は配置配線済み測定回路から
抽出した物理接続で、数値の旧遅延ラベルを含まない。

```sh
cargo build --release \
  --manifest-path toolchain/worktrees/isa/texo-sta-replacement/Cargo.toml \
  --target-dir target/texo-sta-replacement -p texo-cli --bin texo --example measured_jtag_sta
python3 riscv/characterization/run_sta_model.py --output NEW_RUN_DIRECTORY \
  --library toolchain/measurements/2026-09-22-ecp5-sta-replacement/measured-sta-library-v2.json
python3 riscv/characterization/qualify_sta_model.py NEW_RUN_DIRECTORY \
  --legacy-batch-size 20 --transport-retries 3
```

認定コマンドは、全体STA・独立構築したJTCKグラフとの一致・チェック付きbitgenを
通した後にFPGAへ書き込み、267件の命令セット／OS試験を実行する。
RTLソース、ELF、命令数、固定仕事量のサイクル数、コンソール出力も従来認定と比較する。
失敗時は直前の実機認定済みCPUへ復帰する。認定完了前には既定プロファイルを変更しない。

採用済みの既定入口は `riscv/tools/texo-measured`。完全なSTA表、実測配置モデル、
各194 psの予約を指定し、認定済みバイナリ・モデルの変更をハッシュで検出する。
実機用イメージは `riscv/build/riscv-hardware-compact-atomic-measured-sta-124p8-20260922.bit`。
旧配置のみのプロファイルとイメージは比較・復旧用として保持する。

実機接続はWindows側 `windows_d2xx_xvc_reopen.py` を使用し、接続ごとにFTDIを開閉する。
最終認定中のUSB通信断3回は失敗ログを保存して該当バッチを再実行した。
成功ログの連結とハッシュも検証する。機能不合格やカウンタ差は再試行で隠さない。
以前の通信失敗試行は `qualification-connection-failed-*`、接続の根拠は
`transport-sta24.json` に保存した。USB／ドライバ障害の根本原因は未確定。
